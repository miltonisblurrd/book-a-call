Yes, when it makes sense for the product and audience. Dark mode is not a checkbox — it is a second surface that needs the same design discipline as the default theme. I design color tokens and contrast rules so both modes stay readable and consistent, then test common components to make sure nothing breaks when the palette inverts.

## What I design for both modes

**Color tokens and contrast**
- Semantic roles for background, surface, text, border, and accent colors
- Contrast ratios checked against WCAG targets in both themes
- States like hover, focus, disabled, and error tested in each mode

**Component coverage**
- Tables, charts, forms, and navigation in real product density
- Data visualization colors that remain distinguishable in dark UI
- Modals, toasts, and overlays that do not blow out or disappear

**When dark mode is optional**
- UI still designed to look intentional in low-light contexts
- Screenshots and marketing assets planned for both backgrounds
- System preference support or manual toggle — depending on product needs

Done right, both modes feel like part of one system — not like light mode with inverted colors pasted on top.
