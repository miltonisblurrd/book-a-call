Yes. I design and implement UI that changes based on user roles and permissions, like admin versus member views. Done right, role-based UI feels seamless to the user instead of confusing or broken.

## How role-based UI is planned

**Roles mapped before screens are designed**
- Permission matrix defining what each role can see, edit, and delete
- Navigation and dashboard layouts tailored to each role's primary tasks
- Shared components with role-aware variants so logic does not create a mess

**Edge cases handled early**
- What happens when a user loses access mid-session
- Empty states for roles with limited data or pending approval
- Upgrade prompts and gated features that feel helpful, not punitive

**Reusable patterns across the app**
- Consistent component library with role logic baked into variants
- Clear visual cues when content is restricted or read-only
- Testing across roles before launch so nothing ships half-broken

Role-based UI is where clarity matters most. Users should never wonder why a button disappeared or why they cannot see data a colleague can. Good role design makes permissions feel invisible.
