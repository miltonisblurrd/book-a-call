Every project follows the same backbone: align early, ship in structured sprints, and launch with QA — so you always know what is happening and what comes next. No black boxes, no mystery progress.

## The four phases

**1. Discovery**
- Kickoff to align on goals, users, scope, and success metrics
- Competitive review, technical requirements, and timeline mapping
- Shared doc with decisions so nothing gets lost between meetings

**2. Design**
- Wireframes or visual direction, then high-fidelity screens
- Structured review cycles with clear feedback windows
- Prototypes for validation before anything goes to build

**3. Build**
- Development in sprints with working builds you can review early
- Integrations, CMS setup, API connections, and content population
- Async updates so you are not waiting on status meetings

**4. Launch**
- QA across devices, browsers, and key user flows
- Performance pass, metadata, and basic SEO structure
- Deployment, redirect setup, and post-launch support window

## What keeps it smooth

Defined milestones, honest scope conversations, and a single point of contact. If priorities shift mid-project, we adjust the plan together instead of letting scope creep silently.
